# AI_LOG

Инструменты: Cursor (модель Grok 4.7) и Claude Code (модель Claude Opus 5.5).

Сначала отдал ассистенту PDF и попросил рабочий API: тарифы, платёж, вебхук, копейки, промокод, рассрочка, статусы. Каркас заработал, но смотреть его было тяжело: код лежал кучей, параметры ручек повторялись, а документация не была собрана. Ниже то, что я после этого поправил сам.

Зависимости вынес в отдельный файл. `Depends`, заголовки и query-параметры сначала были прямо в ручках: сессия, `Idempotency-Key`, фильтры списка, подпись вебхука. На четырёх эндпоинтах это ещё терпимо, на следующих начало бы копироваться. Собрал их как готовые типы. Ручка принимает тип и передаёт данные в сервис, сама параметр не описывает. Новую ручку так проще добавить, не разнося одни и те же заголовки по файлам.

Структуру разложил по папкам. Первая версия была плоской: логика, запросы к базе и HTTP жили рядом. Я разделил слои. Роутер только принимает запрос. Сервис держит правила и транзакцию: промокод, график, статусы. Репозиторий только читает и пишет. Модели, схемы и подключение к базе лежат отдельно. Слой зависит только от того, что ниже, поэтому правило про копейки или переход статуса не расползается по ручкам.

Swagger тоже собрал отдельно. Описания сначала не были нормальной документацией: не было общего каталога ошибок и примеров, по которым можно вызвать ручку из `/docs`. Тексты и примеры вынес в одно место и подключил их только в декораторе ручки: краткое описание, тело запроса, ответы. Каталог ошибок лежит в общем описании API. Примеры `401`, `404` и `409` берутся из тех же исключений, которые сервис реально отдаёт, а не из текста, написанного рядом. Тест открывает схему и сверяет примеры с ответом API, чтобы документация не разъехалась с кодом.
